# 04. Documentation Engine Layer (Layer 3)

> **Reference**: [AGENT_BLUEPRINT.md](file:///d:/project/ai_now_know/AGENT_BLUEPRINT.md) - Section 5 & Section 6

---

## 1. Purpose & Scope

The **Documentation Engine** generates a path-mirrored documentation hierarchy inside `.agent-docs/` matching the repository's source code layout. When a developer inspects any source file, there is an equivalent structured markdown document describing its purpose, public API, dependencies, call graph, and recent changes.

**Core Documentation Principles**:
- **Derived Output**: `.agent-docs/` is strictly derived. If code disagrees with documentation, code is the source of truth.
- **Anti-Hallucination Guardrails**: Documentation must reference only verified symbols and files existing in AST memory.
- **Cost-Controlled Granularity**: Never generate expensive Level 3 docs indiscriminately.

```text
Target Repository:
  src/
    auth/
      session.rs

Mirrored Documentation:
  .agent-docs/
    src/
      auth/
        session.md
```

---

## 2. Four Documentation Levels & Cost Controls

| Level | Content Scope | Generator Engine | Invocation Policy | Cost Profile |
|---|---|---|---|---|
| **Level 0: Raw Facts** | File path, AST symbols, line ranges, imports, exports | Tree-sitter AST (No LLM) | Always generated on every scan | Free / Deterministic |
| **Level 1: Basic Summary** | 1-2 sentence purpose statement | Fast LLM (gpt-4o-mini / Haiku) | Auto-generated for changed files | Inexpensive (< $0.001/file) |
| **Level 2: Detailed Explanation** | Behavioral overview, caller context, typed error modes | Medium LLM (Claude 3.5 Sonnet) | Only for changed high-risk files | Selective |
| **Level 3: Deep Architecture** | Full API docs, call graphs, risks, known issues, test mappings | Frontier LLM (Sonnet 4 / Claude 3.7) | Configured core paths or manual request | High value / On-demand |

## 3. Strict Frontmatter Specification

Every mirrored markdown document must prepend YAML frontmatter recording its cryptographic provenance:

```markdown

doc_level: 1

```

---

## 4. Anti-Hallucination Rules

To prevent LLM documentation drift:
1. **Fact Verification**: Level 0 documentation must be composed entirely of deterministic facts parsed by Tree-sitter.
2. **Symbol Grounding**: LLMs generating Level 1-3 docs are provided only existing symbols from the `symbols` table.
3. **Unverified Marking**: If an LLM suggests an unconfirmed dependency or internal call, the generator explicitly annotates it as `*(Unverified)*` rather than inventing an API.
4. **No Signature Invention**: Function signatures and type signatures are extracted directly from code AST and never hallucinated.

---

## 5. Staleness Cascade Policy

When a source file is edited or committed, dependent documentation updates must not trigger a runaway cost explosion:

```text
Change to `src/auth/session.rs`:
  ├── Direct changed file (`session.rs`) ──► Stale immediately (regenerate Level 0/1)
  ├── Direct dependents (`middleware.rs`) ──► Marked 'maybe_stale' in docs table
  └── Transitive dependents (routes, etc.) ──► Marked for review only (DO NOT auto-regenerate)
```

- **Direct Changed File**: Instantly marked `status = 'stale'`. Deterministic Level 0/1 docs regenerate automatically.
- **Direct Dependents**: Marked `maybe_stale`. Only regenerated if their public interface is directly affected.
- **Transitive Dependents**: Never auto-regenerated by default; verified on-demand during scheduled maintenance.

---

## 6. Document Verification (`kaioken docs verify`)

The verification engine audits `.agent-docs/` consistency:
1. Confirms the backing source file still exists on disk (flags orphaned docs).
2. Verifies whether `source_hash` in frontmatter matches the current file hash on disk.
3. Validates that all referenced symbols currently exist in the SQLite `symbols` table.
4. Checks that mirrored filesystem paths match source paths 1-to-1.
