## Why this exists

The developer tools landscape in 2026 is saturated with AI coding assistants: Cursor, GitHub Copilot, Windsurf, Aider, Cline, Continue, and dozens of open-source terminal agents. 

If Kaioken launches with the pitch *"An AI coding agent that writes code and chats with your repo,"* it fails instantly. Prospective users will ask: *"Why would I switch from Cursor or Aider to an unknown tool built by one person?"* Competing on raw chat speed, inline autocomplete, or multi-file code generation against venture-backed companies burning millions of dollars in compute subsidies is a guaranteed loss.

Kaioken was never designed as a chat client. As articulated in the project architecture ([`kaioken_v2/README.md`](file:///D:/project/ai_now_know/kaioken_v2/README.md) and [`roadmap/README.md`](../../README.md); `UNVERIFIED: kaioken_v2/KAIOKEN-THESIS.md` is cited in `roadmap/README.md:444` but not present in the working tree), its core thesis is fundamentally different: **repository knowledge must be durable, verified, and provenance-tracked, outliving any single chat session**. 

This leaf codifies the core launch narrative, the one-sentence claim, and the defensible answers to the inevitable skepticism from developers.

## The launch narrative

### The One-Sentence Claim
> **"Kaioken is the repository knowledge engine that compiles your codebase into verified, provenance-tracked ground — so AI coding agents stop hallucinating your architecture."**

### The Core Argument
1. **The Context Window Is Not a Memory Bank:**
   Shoving 50 raw source files into an LLM context window is expensive, slow, and noisy. Models miss critical boundary conditions because they are forced to reconstruct the architecture from scratch on every single prompt.
2. **Knowledge Should Be Compiled, Not Inferred On The Fly:**
   Software has compilers that translate source code into machine executables. Codebases need an engine that translates source code into **verified architectural documentation**: module hierarchies, symbol dependencies, structural invariants, and task skills.
3. **Verification Before Commitment:**
   Every card written by `kaioken cards` and every chapter generated by `kaioken wiki` undergoes multi-pass verification against the Tree-sitter AST index (`packages/model/src/index.ts:48-52`). If a generated document claims a function exists that does not appear in the scan, the claim is flagged or rejected.
4. **Symbiosis, Not Competition:**
   Kaioken does not demand that you abandon Cursor, VS Code, Claude Code, or Aider. Kaioken makes those tools **drastically smarter**. By running `kaioken init` and exposing an MCP server or `AGENTS.md`, every tool in your workflow reads pre-computed, verified repository ground instead of guessing.

## Answering the standard objections

| Skeptical objection | Defensible Kaioken answer |
|---|---|
| *"Why not just use Cursor / Windsurf / Claude Code?"* | "Use them! Kaioken isn't trying to replace your editor. Kaioken is the knowledge engine that runs in your terminal and CI. It indexes your architecture, verifies facts against ASTs, and writes `.kaioken/` files that Cursor and Claude read via MCP. When your team commits code, Kaioken updates the ground." |
| *"Documentation generators always get out of date."* | "Traditional doc generators rot because nothing tests them. Kaioken treats documentation drift like a failing unit test: `kaioken status --check` runs in your CI pipeline. If a PR changes a function signature without updating the corresponding knowledge card, CI fails." |
| *"Isn't this just RAG over my codebase?"* | "Standard RAG splits files into arbitrary 500-token text chunks and embeds them. When you query RAG, it retrieves five random chunks with zero architectural context. Kaioken parses real AST symbol trees, maps module dependencies, and generates coherent, multi-chapter wikis with verified citation links." |
| *"Can I run it completely offline?"* | "Yes. Phase 1 scanning, Tree-sitter indexing, symbol lookup, knowledge graph derivation, and CI drift checking require zero internet, zero API keys, and zero cloud services. You only call a model when synthesizing new prose." |
